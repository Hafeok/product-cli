### The finding of that gate: parameter nesting makes substitution failures correlated

Raw occurrence counts per parameter are `RATIFIER` 13, `MINT_DATE` 13, `BASE_IRI` 9 — higher than
the gate's 28 recorded spans, because **the ratifier's address and the mint date are substrings of
the base IRI itself**. That is why the first attempt's corruption was pervasive rather than local:
the sigil that broke sat in the one parameter carrying two others inside it, at nine sites across
every file class.

Two consequences worth carrying. Substitution failures are **correlated, not independent** — a
nesting relation between parameters propagates one fault to every dependent site. And the gate's
span-counting is the right instrument precisely because it does not care how values compose: it
records what it wrote and reads it back, so nesting is invisible to it.

A corruption that touches everything is also, perversely, the easiest kind for a human to spot. A
single-site one would not have been caught by reading output.

## 3. Gate 2 — the adapter operations, and the probe

`definition` reuses `normalize_locations` unchanged, exactly as the entry probe predicted — no new
normaliser, no host-layer change. `typeHierarchy` is three call sites and needed a new item
normaliser: hierarchy items are not locations, and routing them through the location normaliser would
have kept uri and range while dropping the symbol identity, which is the half the `rdfs:subClassOf`
row needs.

**The opaque `data` blob round-trips by construction rather than by field-copying**: the normalised
item keeps the server's own item verbatim and hands *that* back, so a field a future server adds
survives too. A fixture strikes it, and the mock **refuses an item whose `data` was rebuilt**, making
the failure a live host would show as a silent empty result loud in CI.

### The probe, live

Six of six operations available on `corpus-backend`'s restorable subgraph, through the shipped host
layer, Roslyn `5.11.0-1.26380.4`, ready in ~3s. Both hierarchy directions reproduce the entry probe:
a marker interface resolves to its three implementing command records; a value-object identity type
resolves to its interface supertype.

**The probe earned its existence on its first real run.** Four sibling identity types all *answer*
`prepareTypeHierarchy` with one item; only one returns a supertype. So the asymmetry reads as three
**genuine empty hierarchies**, not three instrument failures. Without the probe those absences would
have entered a proposal graph indistinguishable from a silent tool fault, and at G0.5 the
cross-codebase comparison would have read them as divergence — a finding manufactured out of an
instrument's silence. Prevented before the extractor existed.

### A correction to §5.2's under-advertising bullet

§5.2 cites Roslyn as the observed under-advertising case. Measured under two client handshakes — with
and without `textDocument.typeHierarchy` declared — Roslyn advertises `typeHierarchyProvider: true`
**both times**. It never under-advertised as a *server*; the entry probe's observation was about the
*client* capability the adapter omitted, which is a different pair from the one the probe compares.

The direction is real (`csharp-ls` does not advertise the provider at all) but it is **not evidenced
by Roslyn**, and the fixture is what carries it until a server demonstrates it. The client capability
is now declared because that is correct practice, not because it unblocked anything — measurement
shows it changes nothing about what this server answers.

### The fixpoint

```
3 rounds · 3 rule parses · 9 executions · 13 ms
seed 1630 triples · 130 proposed · 109 entailed (recomputed at build, never stored)
  usage-direct          130  over 1 productive round
  usage-transitive      109  over 2 productive rounds   [entailed, not proposed]
  subclass-transitive     0  over 0 productive rounds   [entailed, not proposed]
```

Parse-once holds — 3 parses against 9 executions — and a fixture asserts `parses == rules` and
`executions == rounds × rules` so it cannot regress.

**Do not read 13 ms as a scale datum.** At 61 types over a schema-only graph the stage is barely
working. The figure to watch against `g-dec-02`'s `revisit_if` is the **130 → 109 ratio**, not the
milliseconds: the transitive rule is the quadratic one, and the full solution is roughly fifteen times
this corpus.

The line between proposed and entailed: *an assertion is proposed when it is not recomputable from
the proposal set.* The containment join qualifies — its inputs are reference positions that never
enter the registry. The two closures do not, so they are measured and discarded.

### The extraction predicate's closure record

The predicate closed on every row that has an instrument. The declared rows compute their verdict
from the language's own declarations; the structural and heuristic rows compute theirs by rule.
Nothing was judged and nothing halted. One row has no instrument on this surface and is reported as
such.

**But the predicate that closed is narrower than the one a reviewer needs, and the corpus made that
visible.** "Is this a declared type" closed completely. "Is this a *domain* type" was never the
predicate, was never computed, and is where the reviewer's work actually falls — **including on the
declared rows**, which §5.2 does not anticipate. See §7.1.

## 6. The re-run at a second ref — §5.5 and the Q21 decay mechanism

The extractor was run at baseline `b8aba87` (2026-05-19) and at `3b0a56b3`, both writing nothing, and
the two proposal sets diffed by assertion id.

```
baseline b8aba87 : 542 assertions, 57 declarations
later    3b0a56b : 561 assertions, 61 declarations

candidates added     : 22   classes 4 · modules 6 · properties 3 · subclass 1 · synonyms 4 · usage 4
symbols disappeared  :  3   properties 3
unchanged            : 539
```

The 22 additions are four types introduced in the primitives project — a marker interface, two
serialisation converters, and an identity type — with their module, synonym, hierarchy and usage
triples. The 3 disappearances are the three property assertions of a **boolean feature-flag property
removed from a configuration options type**, verified independently against the corpus diff: present
at the baseline, absent at the later ref.

That is the holding note's Q21 decay-of-relevance mechanised, on real code, with no second language
and no drift-detection machinery — it falls out of content-addressed identity and the file set.

**A first attempt at this was vacuous and is recorded as such.** Run initially against the entry
probe's ref, two commits back, the diff was empty — correctly, because the intervening commits touched
only files outside the read subset (confirmed by `git diff --stat`). An empty diff exercises the
mechanism's plumbing but not the decay detection, so the baseline was moved to a ref with real churn.

## 7. Findings for the PRD

Reported, not applied. Edits ride a later PR.

### 7.1 The extraction table needs a second axis — **ranked first**

§5.2's assurance column conflates two independent things:

- **Derivation confidence** — how reliably the instrument read the code.
- **Domain relevance** — whether the result is the kind of thing the registry is for.

The corpus proved they are independent. **Group B is 31 assertions at `high` assurance, every
mechanical check passing, the instrument having read the code perfectly, and every one of them wrong
to ratify.** They are private serialisation state on infrastructure types. Group A is 18 more —
generated schema-change scripts proposed as class candidates, spread across four rows and all three
grades.

§5.2 says the declared rows are where extraction closes and review earns its keep on the inferred
ones. That is now **measured as wrong**: the declared rows are where the largest single block of
rejections sat, and it sat there at the top grade.

Proposal: rows carry `derivation_confidence × domain_relevance`. High/high ratifies at pace;
high/low — code read perfectly, irrelevant to the registry — is exactly the 49.

**The forcing argument is recoverability, not convenience.** Group A is recoverable from the graph
after the fact, via the `reg:evidence` paths its assertions carry. **Group B is not recoverable from
the graph at all** — nothing in a ratified assertion records that its property came from a field
rather than a property, and the count had to be taken from the extractor's own JSON output. A future
reviewer re-examining this class of error cannot find its members. That is not a reporting gap; it is
**ground that cannot be audited**, and it makes marking derivation on the Reading non-optional rather
than nice to have.

### 7.2 Widening the declaration-level subset should be a filed decision

Both practical faces of §7.1 have cheap remedies that are **out of the current subset**:

- Generated code carries markers — attributes, a folder convention, a generated-file header — none of
  which appear in `documentSymbol` output.
- Visibility is already derived from source text by the C# adapter's own facts layer, which the
  extractor does not use because it is outside the declaration-level six.

The subset was chosen to keep the extraction predicate closing, and it does close — on a predicate
narrower than useful. Widening it is the obvious next move and should be **a filed decision with the
closure consequence stated**, not a quiet extension: each widening trades constructive closure for
relevance, and the trade should be recorded where it can be revisited.

### 7.3 The entailment stage is correct and idle

`subclass-transitive` fired **zero** times across 17 hierarchy edges: every declared derivation in
this corpus is one level, type → marker interface. With a schema-only graph and no instance data, the
RDFS/OWL-RL stage's entire available yield *is* subclass transitivity, and this corpus has none.

Recorded prominently so no later reader of the manifest concludes the reasoner is doing work. It is
wired, tested, and currently contributing nothing.

### 7.4 Per-triple review does not scale, and the answer is the same second axis

561 files is already at the edge of per-triple review, and the full solution is roughly fifteen times
this corpus. The answer is not wholesale merge — that is manufactured ground by §5.6. It is review
**batched by derivation confidence × domain relevance**, which is §7.1 arriving from the review side
rather than the extraction side. Two independent routes to the same change.

### 7.5 `definition` is wired but unspent

Two of the six operations answer and no mapping row consumes them: `workspaceSymbol` and
`definition`. The reads take the per-file route, and range resolution matches on simple name, which
is safe **on this corpus** — 0 cross-module name collisions, measured. `definition` is the
exact-resolution route if collisions appear at full-solution scale, so it is insurance rather than
waste. Worth recording that Gate 2's wiring bought a capability the extractor does not yet spend.

### 7.6 Explanatory output is review infrastructure, not debug detail

The extractor's notes — which properties carry no range, which came from fields, which types are
partial — were typed `#[serde(skip)]`, i.e. as debug detail. They are the reviewer's **batching
keys**. Two hand-counts were wrong before the notes were made queryable (13 fields is not 31
assertions; a hardcoded list taken from a report that had truncated at six). General shape: an
instrument's account of its own limits belongs in its output contract, not in its logs.

### 7.7 Three collapsed report states

"Nothing written — planned only" covered a dry run, a run with nothing new to propose, and a run whose
files were already byte-identical. Three states rendering as one passing line — the presumed-discharge
pattern in miniature, inside our own instrument. Split.

### 7.8 Smaller observations against the table

- **Nullability is read and discarded.** 20 properties declare it; expressing it needs OWL cardinality
  restrictions, outside the row's stated output. Nothing wrong is in the graph; something known is
  missing from it.
- **Doc summaries reach the extractor unmapped.** `hover` returns the declaration's summary verbatim;
  the synonyms row's output vocabulary has nowhere to put it.
- **The synonyms row may be specified wrong.** A word split over an identifier is a *spelling*, not a
  synonym — and the weakest thing that satisfies a row's stated output is usually a sign the output
  was mis-specified.
- **`partial` means a declaration count is not a type count**, and same-name-in-one-module (one type)
  must not be reported as same-name-across-modules (two types). Reported as one number, it says the
  wrong thing about both.
- **A nested type's module is its namespace, not its enclosing type.** Reading the innermost container
  proposed three module axes named after classes.

## 8. Mechanics carried from the Oxigraph manifest

| Input | Disposition |
|---|---|
| `SparqlEvaluator::prepare` | Rules parsed once, cloned per round. 3 parses / 9 executions, fixtured. Wall-time recorded; see §4 on why the ratio matters more |
| Registry Turtle from our own writer | Fixed field order, sorted evidence, no blank nodes, one assertion per file. The oxigraph serialiser is transport and inspection only |
| Blank-node re-minting | Nothing to bite on — the template reifies onto a minted IRI. The writer emits no blank node at all, and the store→triple conversion drops any quad carrying one |
| Drain-before-insert | Every CONSTRUCT drained before writing back; the triple iterator borrows the store |

**Reading identity, in full.** An assertion's identity is `sha256(subject, predicate, object)` — not
the run, not the `as_of`, not the assurance. Three consequences, each fixtured and each demonstrated
live: re-running at the same ref proposes nothing and leaves the tree byte-clean; re-running at a
later ref proposes only the delta; a disappeared symbol leaves a ratified file with no counterpart.

The limit, ruled and filed as `g-dec-04`: because the Reading shares the assertion's identity, a
**re-confirmation at a later ref is not recorded**. Writing a fresh `as_of` is a rewrite, which
supersession-not-rewriting forbids; giving the Reading its own node needs a file carrying no assertion
and no decision, which the file rule rejects. Both are format changes rather than instance ones.

At volume, content-addressed identity is what makes review possible at all: sequential numbering would
make every second run's diff total churn.
